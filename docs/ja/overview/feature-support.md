# 🧩 機能サポート状況

すべての公式 Player は **同じコア** でアニメーションを評価します。したがって機能セットは
エンジンごとに作り直されるのではなく共有されており、その一覧は
[SDK コンセプト](../sdk/concepts.md) に掲載しています。それでも差が出るのは次の 3 点です。

1. **エンジンの描画層が再現できる範囲** - 特にブレンドモードは、ホストエンジンが提供する
   固定機能のブレンドステートへの割り当てになります。
2. **各 Player の実装がどこまで進んでいるか** - Player ごとに進捗が異なります。
3. **API の形** - ホストの流儀に合わせて意図的に分けている部分がわずかにあります。これは欠落
   ではないため、下に別の節を設けています。

このページで扱うのは、この **Player 間の差分** のみです。*すべての Player に共通* する制約
（シーク・逆再生の挙動、ブレンドの条件、ブラウザ要件、コアが状態計算のみを行い描画・再生は
Player に委ねている機能）は [共通の制限事項](../sdk/limitations.md) にまとめてあります。

## 🔍 ドキュメントに記載されている Player ごとの差分

| Player | 既知の差分 |
|---|---|
| **[Unity](../players/unity.md)** | **uGUI（Canvas）パス** は CanvasRenderer の「1 レンダラー = 1 メッシュ + 1 マテリアル」に合わせるため、**単一アトラス前提**（他のアトラスのパーツは正しく参照できない）で、**MIX / ADD のみ**対応し、それ以外のブレンドは `Mix` に集約されます。ワールドパスにはどちらの制約もありません。`.ssqb` は**インポート**して参照できます。シーケンスとしての再生が未対応なのは Unity 固有ではなく[全 Player 共通](../sdk/limitations.md)です。編集モードでは開始フレームの静止プレビューのみが表示されます。 |
| **[Web](../players/web.md)** | レンダラーパッケージ（`ssplayer-webgl`・`ssplayer-pixi`）自体に機能面の欠落はありません。フレームワーク連携は成熟度が異なり、**RPG ツクール MZ は実験的（alpha）**（ピクチャの色調がアニメーションに影響しない）、**TyranoScript・ティラノビルダー向けプラグインは beta** です。ティラノビルダーはパーツ単位の色・表示切り替えと、アニメーションと話者の紐付けに対応するコンポーネントがまだなく、これらは `[ss_*]` タグで記述します。ブラウザ版コンバーター `ssconverter-web` は File System Access API を使うため **Chromium 系ブラウザ限定**です。 |
| **[Godot](../players/godot.md)** | 共通の制約を超える機能面の欠落はありません。GDExtension と カスタムモジュールの 2 形態で提供され、**Web 書き出し** のみ追加要件があります（GDExtension には `dlink_enabled` 有効のエンジンテンプレートが必要。カスタムモジュールでは不要）。また Web はシングルスレッド（`nothread`）動作のため、COOP/COEP ヘッダーは不要です。 |
| **[Flutter](../players/flutter.md)** | 描画バックエンドが 2 種類（`flutter_gpu` / Canvas。Web は常に Canvas）。Canvas では `Sub`・`Invert` を 3 パスで再現するためバッチングできません。`Div2`・`Overlay2` は**両バックエンドとも** `Mix` として描画されます。ウィジェットの**パーツトラッキング**は変換のみを転送し描画順は含まないため、追従したウィジェットはパーツの間ではなくアニメーション全体の手前に描画されます。ビューが等倍で描画される前提でもあります。 |
| **[Ren'Py](../players/renpy.md)** | Division・Overlay は `Mix` にフォールバックします。**パーツトラッキング**は変換のみを転送し描画順は含まないため、追従した子はパーツの間ではなくスプライト全体の手前に描画されます。マスク、メッシュパーツのパーツ全体の色、インスタンスパーツ *内部* に対する操作は、厳密ではなく近似的な挙動になります。個別の内容は Ren'Py 自身のドキュメントに列挙されています。 |
| **[React Native](../players/react-native.md)** | **マスク付きのメッシュとエフェクトはマスクなしで描画されます** - マスクの再現はアフィン変換された 1 枚のクアッドの UV を逆算してカバレッジを参照する方式で、メッシュはその texcoord チャンネルをアトラスに使っており、エフェクトは 1 枚ではなくクアッドの集合だからです。また、外側からマスクが届いているフレームでは、**子が持つマスクの書き込みが無効**になります。対応プラットフォームも狭く、tvOS・visionOS は Rust の Tier 3 ターゲット待ちで、Windows には経路がありません。 |
| **[wgpu](../players/wgpu.md)** | `Div2`・`Overlay2` は `Mix` にフォールバックします。マスクは**ステンシルのみ**で、INCR と INVERT が混在する重なりは近似になり、入れ子は 8 ビット分に制限され、25 個目以降の書き込みは破棄されます。グループアルファは**パーツを 1 つずつ**合成するため、`0.5` の 2 パーツが重なった部分は `0.5` ではなく `0.75` になります。13 種の連携シェーダーは **Normal パーツのみ**対応で、`map0`・`map1` の副テクスチャや、マスクと併用したシェーダーパーツは対象外です。 |

!!! note "この表の読み方"
    各行は、その Player 自身の **制約と適用範囲** ページに記載された内容の要約です。個別の
    ケースはリンク先を参照してください。このページはすべての Player が公開しています。ただし
    wgpu だけは例外で、ドキュメントサイトが公開されるまでは
    [ROADMAP](https://github.com/cri-middleware/SSPlayerForWgpu/blob/HEAD/ROADMAP.md) が同じ
    役割を担っています。したがって、ここに載っていない事項はその Player 自身の記述にもない、
    ということになります（対応の保証ではありません）。

    *すべての* Player に当てはまることは差分ではないため、この表ではなく
    [共通の制限事項](../sdk/limitations.md) に記載しています。**テキストパーツと 9 スライス
    パーツがどの Player でもまだ描画されない**ことも、そちらに含まれます。

## 🎨 ブレンドモードで差が出やすい理由

SpriteStudio のブレンドは GPU のブレンドステートとして実現されるため、再現度はホストエンジンが
何を提供しているかに依存します。相当するモードがない場合、Player は失敗せずフォールバックします。
上表の差分が特定のモードに集中しているのはこのためです。

- **Division / Overlay** は参照実装の Player にも GPU ブレンドの対応がなく、`Mix` への
  フォールバックは実装が未完なのではなく意図的な挙動です。
- **Sub / Invert** には reverse-subtract または destination-replace のステートが必要です。それを
  持たないエンジンでも複数パスで厳密に再現できますが、バッチングは犠牲になります。つまり差は
  見た目ではなくパフォーマンスとして現れることがあります。

なお、Player 側に非がなくてもブレンドが意図どおりに見えない場合があります。描画先を参照する
モードは、下のピクセルが不透明であることを前提とするためです。これは全 Player 共通の性質で、
[共通の制限事項](../sdk/limitations.md) に記載しています。

## ⚙️ 意図的な差 - 欠落ではありません

上の表は「まだ再現できないもの」でした。この節はその逆で、**互いに揃えるよりホストの流儀に
従うほうが利用者のためになる**ため、意図的に分けている部分です。

### まず、差が *ない* 部分

こちらのほうが大きいので先に書きます。**再生の意味論は全 Player で同一**で、各 Player の発明
ではなく SDK の契約です。

- **トランスポートは 4 つの動詞**で、互いの言い換えではありません。`play` は **頭出し**（区間
  の先頭へ巻き戻し、ループ回数を再武装）なので `pause` の解除には使えません。解除は `resume`
  で、停止中は何もしません。`stop` は巻き戻しません。
- **`isPlaying` は pause 中も true** です。pause は保持であって停止ではなく、両者を区別するの
  は `isPausing` です。
- **`looped` はパルス、`finished` はエッジ**です。`finished` は無限ループでは発火せず、明示的
  な `stop` でも発火しません。
- **すでに選択済みのアニメーションを指定しても何も起きません。** これは切り替えであり、切り替
  え先が無ければ再生ヘッドはそのまま、ループ予算も再武装されず、オーバーライドも残ります。再
  スタートは `play` の役目です。
- **アニメーション切り替えを跨いで残るもの**: 速度・フレームレート上書き・フレームスキップ・
  再生方向 / スタイル。残らないもの: 再生区間（フレーム番号は別のクリップに対して意味を持ちま
  せん）。

### クロックの出どころと単位

時間だけは SDK から受け取れません。ホストごとに測り方が違うためで、tick は各プラットフォーム
の流儀で表現されています。

| Player | 進めるのは誰か | 単位 |
|---|---|---|
| **Unity** | `SpriteStudioUpdateManager` が一括で | （公開 tick なし） |
| **Godot** | ノード自身が `_process` / `_physics_process` で。`ANIMATION_PROCESS_MANUAL` + `advance()` も可 | 秒 |
| **Web** | `SSSurface` のティッカー（`ssplayer-webgl`）／`Ticker.shared`（`ssplayer-pixi`） | ミリ秒 |
| **Flutter** | `vsync` を渡せば `Ticker`、渡さなければホストが `advance()` | `Duration` |
| **React Native** | View のフレームループ、ヘッドレスなら `startClock()` | ミリ秒 |
| **Ren'Py** | displayable の `render()` | ミリ秒 |
| **wgpu** | **ホスト** - クロックはホストが持ち、delta を貸します | 秒 |

### autoplay は「Player がどう生まれるか」で決まります

ここに全 Player 共通の既定はありません。そもそもこの問いが存在しない Player があるためです。

| Player の生まれ方 | autoplay | 理由 |
|---|---|---|
| シーンに **配置**（Unity・Godot） | 既定 **on** | 配置したノードのために `play()` を呼ぶコードは存在せず、静止フレームは壊れて見えます |
| マークアップで **宣言**（`<ss-player>`・`<ss-player-webgpu>`） | 属性による **opt-in** | 属性そのものがその呼び出しであり、HTML の boolean 属性は既定 on にできません（`<video autoplay>` と同じ形） |
| コンポーネントで **宣言**（`<SpriteStudioView playing>`） | prop、既定 **on** | React の prop は状態であって一度きりのフラグではありません |
| displayable として **show**（Ren'Py） | 常時 | `show` は「画面にあって動いている」という意味です |
| コードで **生成**（Web の JS API・Flutter・wgpu） | 概念なし | 呼び出しはすでに手元にあります |

### サブフレーム補間はホストに合わせています

描画がサブフレーム位置に載ることを許すかどうかです。再生ヘッドはどちらでも小数で、これが決め
るのは描画フレームを切り捨てるかだけです。

| 既定 | Player |
|---|---|
| **off** | Unity・Godot - ゲームエンジンでは authored フレームに固定するのが通例です |
| **on** | Web・Flutter・Ren'Py・React Native・wgpu - アプリやレンダラでは、authored より速いリフレッシュレートに追従することが目的です |

いずれの Player も setter を持つので、これは制限ではなく既定値です。

### イベントの受け口はホストの流儀

同じイベント（ユーザーデータ・シグナル・オーディオ、およびループと完了）を、各プラットフォー
ムの形で配ります。

| Player | 形 |
|---|---|
| **Godot** | シグナル（`user_data`・`signal_emitted`・`audio`・`animation_finished` ほか） |
| **Unity** | C# の `event` **と** `UnityEvent`。コードからもインスペクタからも購読できます |
| **Web** | `onX(listener)` が unsubscribe を返す形 |
| **Flutter**・**React Native** | Player 上のコールバックフィールド |
| **Ren'Py** | フレーム結果として観測、加えて上限付きの `poll_events()` キュー |
| **wgpu** | ポーリング。update のあとに `events()`（borrow model に合わせた形） |

### パックの読み込み

| Player | 形 |
|---|---|
| **Unity**・**Godot** | エンジンのアセット参照。エディタのインポータが解決する同期処理 |
| **Web**・**React Native** | URL またはソース記述子から非同期 |
| **Flutter** | バイト列から非同期（`loadAsset` が読み出しも行います） |
| **Ren'Py** | displayable にパスを渡し、初回 render で遅延読み込み |
| **wgpu** | パスから同期、またはホストが渡す `AssetLoader` 経由で非同期 |

アニメーションの選択は **どの Player でも同期** です。これは意図的で、時間のかかりうるもの
（テクスチャ・インスタンスパック・サウンド）はアニメーションではなく **パック** に属し、読み
込み時に済ませてあるためです。
