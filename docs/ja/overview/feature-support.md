# 🧩 機能サポート状況

すべての公式 Player は **同じコア** でアニメーションを評価します。したがって機能セットは
エンジンごとに作り直されるのではなく共有されており、その一覧は
[SDK コンセプト](../sdk/concepts.md) に掲載しています。それでも差が出るのは次の 2 点です。

1. **エンジンの描画層が再現できる範囲** - 特にブレンドモードは、ホストエンジンが提供する
   固定機能のブレンドステートへの割り当てになります。
2. **各 Player の実装がどこまで進んでいるか** - Player ごとに進捗が異なります。

このページで扱うのは、この **Player 間の差分** のみです。*すべての Player に共通* する制約
（シーク・逆再生の挙動、ブレンドの条件、ブラウザ要件、コアが状態計算のみを行い描画・再生は
Player に委ねている機能）は [共通の制限事項](../sdk/limitations.md) にまとめてあります。

## 🔍 ドキュメントに記載されている Player ごとの差分

| Player | 既知の差分 |
|---|---|
| **[Unity](../players/unity.md)** | **uGUI（Canvas）パス** は CanvasRenderer の「1 レンダラー = 1 メッシュ + 1 マテリアル」に合わせるため、**単一アトラス前提**（他のアトラスのパーツは正しく参照できない）で、**MIX / ADD のみ**対応し、それ以外のブレンドは `Mix` に集約されます。ワールドパスにはどちらの制約もありません。`.ssqb` は**インポート**して参照できます。シーケンスとしての再生が未対応なのは Unity 固有ではなく[全 Player 共通](../sdk/limitations.md)です。編集モードでは開始フレームの静止プレビューのみが表示されます。 |
| **[Web](../players/web.md)** | レンダラーパッケージ（`ssplayer-webgl`・`ssplayer-pixi`）自体に機能面の欠落はありません。フレームワーク連携は成熟度が異なり、**RPG ツクール MZ は実験的（alpha）**（ピクチャの色調がアニメーションに影響しない）、**TyranoScript・ティラノビルダー向けプラグインは beta** です。ティラノビルダーはパーツ単位の色・表示切り替えと、アニメーションと話者の紐付けに対応するコンポーネントがまだなく、これらは `[ss_*]` タグで記述します。ブラウザ版コンバーター `ssconverter-web` は File System Access API を使うため **Chromium 系ブラウザ限定**です。 |
| **[Godot](../players/godot.md)** | 共通の制約を超える機能面の欠落はありません。GDExtension と カスタムモジュールの 2 形態で提供され、**Web 書き出し** のみ追加要件があります（GDExtension には `dlink_enabled` 有効のエンジンテンプレートが必要。カスタムモジュールでは不要）。また Web はシングルスレッド（`nothread`）動作のため、COOP/COEP ヘッダーは不要です。 |
| **[Flutter](../players/flutter.md)** | 描画バックエンドが 2 種類（`flutter_gpu` / Canvas。Web は常に Canvas）。Canvas では `Sub`・`Invert` を 3 パスで再現するためバッチングできません。`Div2`・`Overlay2` は**両バックエンドとも** `Mix` として描画されます。ウィジェットの**パーツトラッキング**は変換のみを転送し描画順は含まないため、追従したウィジェットはパーツの間ではなくアニメーション全体の手前に描画されます。ビューが等倍で描画される前提でもあります。 |
| **[Ren'Py](../players/renpy.md)** | **アニメーションブレンドは未実装**で、Division・Overlay は `Mix` にフォールバックします。**パーツトラッキング**は変換のみを転送し描画順は含まないため、追従した子はパーツの間ではなくスプライト全体の手前に描画されます。マスク、メッシュパーツのパーツ全体の色、インスタンスパーツ *内部* に対する操作は、厳密ではなく近似的な挙動になります。個別の内容は Ren'Py 自身のドキュメントに列挙されています。 |

!!! note "この表の読み方"
    各行は、その Player 自身の **制約と適用範囲** ページに記載された内容の要約です。個別の
    ケースはリンク先を参照してください。すべての Player がこのページを公開しているため、
    ここに載っていない事項はその Player のドキュメントにも記載がない、ということになります
    （対応の保証ではありません）。

    *すべての* Player に当てはまることは差分ではないため、この表ではなく
    [共通の制限事項](../sdk/limitations.md) に記載しています。**テキストパーツと 9 スライス
    パーツがどの Player でもまだ描画されない**ことも、そちらに含まれます。

## 🎨 ブレンドモードで差が出やすい理由

SpriteStudio のブレンドは GPU のブレンドステートとして実現されるため、再現度はホストエンジンが
何を提供しているかに依存します。相当するモードがない場合、Player は失敗せずフォールバックします。
上表の差分が特定のモードに集中しているのはこのためです。

- **Division / Overlay** は参照実装の Player にも GPU ブレンドの対応がなく、`Mix` への
  フォールバックは実装が未完なのではなく意図的な挙動です。
- **Sub / Invert** には reverse-subtract または destination-replace のステートが必要です。それを
  持たないエンジンでも複数パスで厳密に再現できますが、バッチングは犠牲になります。つまり差は
  見た目ではなくパフォーマンスとして現れることがあります。

なお、Player 側に非がなくてもブレンドが意図どおりに見えない場合があります。描画先を参照する
モードは、下のピクセルが不透明であることを前提とするためです。これは全 Player 共通の性質で、
[共通の制限事項](../sdk/limitations.md) に記載しています。
