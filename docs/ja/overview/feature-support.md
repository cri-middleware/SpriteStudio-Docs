# 🧩 機能サポート状況

すべての公式 Player は **同じコア** でアニメーションを評価します。したがって機能セットは
エンジンごとに作り直されるのではなく共有されています。それでも差が出るのは次の 2 点です。

1. **エンジンの描画層が再現できる範囲** - 特にブレンドモードは、ホストエンジンが提供する
   固定機能のブレンドステートへの割り当てになります。
2. **各 Player の実装がどこまで進んでいるか** - Player ごとに進捗が異なります。

*すべての Player に共通* する制約（シーク・逆再生の挙動、ブレンドの条件、ブラウザ要件など）は
[共通の制限事項](../sdk/limitations.md) にまとめてあります。あわせてお読みください。

## ✅ 共通コアが提供する機能

以下は `libssruntime` 由来のため、すべての Player で利用できます。

- ボーン階層とトランスフォーム、および全補間方式のキーフレーム補間（Bezier / Hermite / Linear ほか）
- メッシュ・デフォーム
- エフェクトパーツ（パーティクル）
- インスタンスパーツ
- マスク
- パーツカラー（パーツ単位のカラーブレンド）
- フレーム精度のイベント - ユーザーデータ、シグナル、オーディオ
- サブフレーム補間（基準フレームレートを超える滑らかな再生）
- アニメーション全体のブレンド／クロスフェード（同一 `.ssab` 内。
  [共通の制限事項](../sdk/limitations.md) を参照）
- **Override Layer API** - 再生時にパーツのカラー・セル参照・表示状態を上書き

このうち **テキストパーツ** と **オーディオ** は状態計算のみで、グリフの描画と実際の音声再生は
Player 側の実装が必要です（[共通の制限事項](../sdk/limitations.md)）。

## 🔍 ドキュメントに記載されている Player ごとの差分

| Player | 既知の差分 |
|---|---|
| **[Unity](../players/unity.md)** | Player 固有の制限事項は記載されていません。ボーン、メッシュ・デフォーム、パーティクル、拡張ブレンド、マスクに対応し、uGUI（Canvas）描画と Timeline 連携を追加で提供します。 |
| **[Web](../players/web.md)** | レンダラーパッケージ（`ssplayer-webgl`・`ssplayer-pixi`）に機能面の記載された欠落はありません。**RPG ツクール MZ・TyranoScript 向けアダプターは実験的（alpha）** です。 |
| **[Godot](../players/godot.md)** | 機能面の欠落の記載はありません。GDExtension と カスタムモジュールの 2 形態で提供され、**Web 書き出し** のみ追加要件があります（GDExtension には `dlink_enabled` 有効のエンジンテンプレートが必要。カスタムモジュールでは不要）。 |
| **[Flutter](../players/flutter.md)** | 描画バックエンドが 2 種類（`flutter_gpu` / Canvas。Web は常に Canvas）。Canvas では `Sub`・`Invert` を 3 パスで再現するためバッチングできず、`Div2`・`Overlay2` は `Mix` として描画されます。 |
| **[Ren'Py](../players/renpy.md)** | 記載がもっとも多い Player です。**テキスト／NineSlice パーツは描画されません**、**アニメーションブレンドは未実装**、Division・Overlay は `Mix` にフォールバック、マスクはエフェクトのパーティクルをクリップしない、メッシュパーツのパーツ全体の色は近似（α のみ）、パーツの上書きはインスタンスパーツ *内部* のパーツには届きません。 |

!!! note "この表の読み方"
    掲載しているのは、各 Player 自身のドキュメントに記載された内容のみです。記載がないことは
    *ドキュメント化されていない* という意味であり、対応の保証ではありません。正典は各 Player の
    ドキュメントです。Ren'Py の記載が多いのは、書き出されている度合いが高いことも一因です。

## 🎨 ブレンドモードについて

SpriteStudio のブレンドは GPU のブレンドステートとして実現されるため、再現度はホストエンジンが
何を提供しているかに依存します。相当するモードがない場合、Player は失敗せずフォールバックします。

- **Division / Overlay** は `Mix` にフォールバックします（Flutter・Ren'Py の双方で明記）。Flutter の
  ドキュメントによれば、これは参照実装の Player にも GPU ブレンドの対応がないための意図的な挙動です。
- **Sub / Invert** には reverse-subtract または destination-replace のステートが必要です。Flutter の
  Canvas バックエンドは 3 パスで厳密に再現しますが、その再現を持たないバックエンドでは差が出ます。
- 描画先を参照するモード（`Mul`・`Sub`・`Screen`・`Exclusion`・`Invert`）は、下のピクセルが
  **不透明** な場合にエディターと一致します（SpriteStudio 自身がその前提で描画するため）。厳密な
  一致が必要なら、ブレンドを多用するアニメーションには不透明な背景レイヤーを敷いてください。

## ❔ まだドキュメント化されていない事項

- **テキスト／NineSlice パーツ** - 対応状況を明記しているのは Ren'Py のドキュメントのみです
  （未描画）。他の Player は可否どちらも記載していないため、これらを使うプロジェクトでは対象の
  Player で個別に確認してください。
- **シーケンス（`.ssqe`）再生** - ランタイム側が未実装のため、どの Player でも利用できません
  （[共通の制限事項](../sdk/limitations.md)）。
