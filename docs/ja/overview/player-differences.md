# 🧩 Player ごとの違い

すべての公式 Player は **同じコア** でアニメーションを評価します。したがって機能セットはエンジンごとに作り直されるのではなく共有されており、その一覧は
[SDK コンセプト](../sdk/concepts.md) に掲載しています。それでも差が出るのは次の 2 点です。

1. **エンジンの描画層が再現できる範囲** - 特にブレンドモードは、ホストエンジンが提供する固定機能のブレンドステートへの割り当てになります。
2. **各 Player の実装がどこまで進んでいるか** - Player ごとに進捗が異なります。

このページで扱うのは、この **Player 間の差分** のみです。*すべての Player に共通* する制約（シーク・逆再生の挙動、ブレンドの条件、ブラウザ要件、コアが状態計算のみを行い描画・再生は
Player に委ねている機能）は [共通の制限事項](../sdk/limitations.md) にまとめてあります。

## 🔍 ドキュメントに記載されている Player ごとの差分

| Player | 一言で言うと |
|---|---|
| **[Unity](../players/unity.md)** | uGUI（Canvas）パスにのみ、ワールドパスにはない制約がある |
| **[Web](../players/web.md)** | `ssplayer-webgl` のマスクはステンシルバッファが前提。フレームワーク連携は beta |
| **[Godot](../players/godot.md)** | 12 種のブレンドのうち対応は 4 種。Web 書き出しに追加要件 |
| **[Flutter](../players/flutter.md)** | 描画バックエンドが 2 種類。Canvas では 2 つのブレンドでバッチングが落ちる |
| **[Ren'Py](../players/renpy.md)** | `Div2`・`Overlay2` が `Mix` にフォールバック。一部機能は近似 |
| **[wgpu](../players/wgpu.md)** | マスクのバックエンドが 2 つ。Bevy アダプタが描画するビューは 1 つ |
| **[React Native](../players/react-native.md)** | マスクはエフェクトパーツをクリップしない。Web では何も描画されない |

!!! note "このページの読み方"
    以下の各節は、その Player 自身の **制約と適用範囲** ページに記載された内容の要約です。制約と適用範囲のページはどの Player も公開しており、個別のケースはそこに列挙されています。したがって、ここに載っていない事項はその Player 自身の記述にもない、ということになります（対応の保証ではありません）。

    *すべての* Player に当てはまることは差分ではないため、ここではなく
    [共通の制限事項](../sdk/limitations.md) に記載しています。**テキストパーツと 9 スライスパーツがどの Player でもまだ描画されない**ことも、そちらに含まれます。

### Unity

**uGUI（Canvas）パス** は CanvasRenderer の「1 レンダラー = 1 メッシュ + 1 マテリアル」に合わせるため、**単一アトラス前提**（他のアトラスのパーツは正しく参照できない）で、**`Mix` / `Add` のみ**対応し、それ以外のブレンドは `Mix` に集約されます。ワールドパスにはどちらの制約もありません。

編集モードでは開始フレームの静止プレビューのみが表示されます。

### Web

**`ssplayer-webgl` はステンシルバッファでマスクします**。ステンシルバッファの無いコンテキストではマスクを書き込めないため、マスクの外側に描くパーツはマスクされずに描かれ、マスクの内側にだけ描く設定のパーツは描かれません。フレームワーク連携（**RPG ツクール MZ・TyranoScript・ティラノビルダー**）は **beta** で、RPG ツクール MZ ではピクチャの色調とブレンドモードがアニメーションに影響しません。

ブラウザ版コンバーター `ssconverter-web` は File System Access API を使うため
**Chromium 系ブラウザ限定**です。

### Godot

12 種のブレンドのうち**対応するのは `Mix`・`Mul`・`Add`・`Sub` の 4 種だけ**で、`Mulalpha` と `Mul2` は `Mul` として、残る 6 種は `Mix` として描かれます。プラグインは Godot のキャンバスアイテムへ直接描画するため、パーツが使えるのは `CanvasItemMaterial` が対応するモードに限られます。マスクは**エフェクトパーツをクリップしません**。

GDExtension とカスタムモジュールの 2 形態で提供され、**Web 書き出し** のみ追加要件があります（GDExtension には `dlink_enabled` 有効のエンジンテンプレートが必要。カスタムモジュールでは不要）。また Web はシングルスレッド（`nothread`）動作のため、COOP/COEP ヘッダーは不要です。

### Flutter

描画バックエンドが 2 種類（`flutter_gpu` / Canvas。Web は常に Canvas）。Canvas では
`Sub` を 4 パス、`Invert` を 3 パスで再現するためバッチングできません。`Div2`・`Overlay2` は**両バックエンドとも** `Mix` として描画されます。マスクは**どちらのバックエンドでもエフェクトパーツをクリップしません**。Web ターゲットは **developer preview** です。

ウィジェットの**パーツトラッキング**は変換のみを転送し描画順は含まないため、追従したウィジェットはパーツの間ではなくアニメーション全体の手前に描画されます。アンカーはビューと同じ矩形を覆う必要があります。

### Ren'Py

`Div2`・`Overlay2` は `Mix` にフォールバックします。**パーツトラッキング**は変換のみを転送し描画順は含まないため、追従した子はパーツの間ではなくスプライト全体の手前に描画されます。

マスク、メッシュパーツのパーツ全体の色、インスタンスパーツ *内部* に対する操作は、厳密ではなく近似的な挙動になります。また、エフェクトパーツが放出するパーティクルは、エディターがクリップする箇所でもマスクでクリップされません。個別の内容は Ren'Py 自身のドキュメントに列挙されています。

### wgpu

`Div2`・`Overlay2` は `Mix` にフォールバックします。マスクには**バックエンドが 2 つあり、ホストのパスが何を貸せるかで選ばれます**。**ステンシル**方式と、ステンシルを貸せないパスのための**カバレッジビットマップ**方式で、後者はマスクを持つ Player 1 体につき描画パスが 1 つ増え、writer が 24 枚を超えるごとにさらに 1 つ増えます。どちらのバックエンドも writer は 1 体につき 96 枚で止まります。どちらでも、Player が描画するパスは **MSAA を off** にする必要があります。

**Bevy アダプタ**は別クレートで、Player 側ではなく Bevy のリリースラインに追従し、一度に
1 ラインだけを対象とします。Bevy の 2D デプステクスチャはステンシルを持たないためカバレッジ方式が使われます。描画するビューは **1 つ**で、2 つ目のビューは警告付きでスキップされます（色を忠実に出すにはカメラに
`CompositingSpace::Srgb` も必要）。パックは Bevy の `AssetServer` を通して読むので、ホットリロード・パックアセット・アトラス共有は Bevy の他のアセットと同じように効きます。

### React Native

マスクは Normal・Mesh・Shape パーツをクリップし、**エフェクトパーツはマスクなしで描画されます**。

対応プラットフォームも狭く、**Web では何も描画されず**（Web のエントリはスタブなので、両方を含むアプリもそのままバンドルできます）、Windows には経路がありません。

## 🎨 ブレンドモードで差が出やすい理由

SpriteStudio のブレンドは GPU のブレンドステートとして実現されるため、再現度はホストエンジンが何を提供しているかに依存します。相当するモードがない場合、Player は失敗せずフォールバックします。上記の差分の多くが特定のモードに集中しているのはこのためです。

- **`Div2` / `Overlay2`** は参照実装の Player にも GPU ブレンドの対応がなく、`Mix` へのフォールバックは実装が未完なのではなく意図的な挙動です。
- **`Sub` / `Invert`** には reverse-subtract または destination-replace のステートが必要です。それを持たないエンジンでも複数パスで厳密に再現できますが、バッチングは犠牲になります。つまり差は見た目ではなくパフォーマンスとして現れることがあります。

なお、Player 側に非がなくてもブレンドが意図どおりに見えない場合があります。描画先を参照するモードは、下のピクセルが不透明であることを前提とするためです。これは全 Player 共通の性質で、[共通の制限事項](../sdk/limitations.md) に記載しています。
