# ⚠️ 共通の制限事項

このページの内容はすべて **共通コア**（`libssruntime` / `libssab`）に由来するため、エンジンを問わず **すべての公式 Player に当てはまります**。各 Player のドキュメントには、その Player に固有の事項のみが記載されています。Player 間の差分は
[Player ごとの違い](../overview/player-differences.md) を参照してください。

!!! tip "正典の所在"
    実装レベルの完全な一覧は SDK の Player 移植ガイド（[`20_limitations.ja.md`](https://github.com/cri-middleware/SpriteStudio-SDK/blob/HEAD/libs/ssruntime/docs/10_introduction/20_limitations.ja.md) -
    ガイド全体の目次は [`README.ja.md`](https://github.com/cri-middleware/SpriteStudio-SDK/blob/HEAD/libs/ssruntime/docs/README.ja.md)）にあります。このページはその利用者向け要約です。

## 🎬 再生・タイムライン

### `independent = true` パーツは逆再生・シークで正しく動作しない

`independent = true` を設定したインスタンスパーツ／エフェクトパーツは、親のタイムラインから切り離され **自身のリアルタイム時計** で進行します。そのため親の **逆再生** と **シーク** で破綻します（リアルタイム時計は過去方向に戻れず、任意の過去フレームにおける「子の累積時間」も一意に定まらないため）。順方向の再生は、順方向のフレームスキップを含めて正しく動作します。

**対処:** 逆再生やシークを行う可能性のあるアニメーションは、`independent = true` を使わない構成で制作してください。やむを得ず使用する場合は、その子インスタンスが順方向再生時のみ正しく描画されることを Player の利用者に明示してください。

### シークは通過したフレームのイベントを発火しない

再生位置を直接ジャンプさせた場合（フレーム指定）、発火するのは **移動先フレーム** の
`UserData` / `Signal` / `Audio` イベントのみで、通過した各フレームのイベントは発火しません。

**対処:** 中間のイベントも漏れなく処理したい場合は、ジャンプではなく `update()` を複数回呼んで少しずつ進めてください。

### オーディオは逆再生できない

一般的なオーディオバックエンドは音声の逆再生を提供していないため、音が鳴るのはアニメーションが時間軸上を **順方向** に進んでいる間のみです。実質的な進行方向が逆向き（逆再生、ピンポンの復路）の場合も、ランタイムはオーディオイベント自体は通知し、抑止されるのは音の再生だけです。組み込みの音声再生を持つ Player は再生をスキップし、イベントをアプリへ渡す Player では再生前に `isPlayingForward`（`is_playing_forward`）で判定します。

負の再生速度はこれに **該当しません**。速度は倍率であり、負値は再生ヘッドの向きを変えるのではなく停止させます。逆方向への再生は再生方向の担当です。速度 `0` も同じく停止します。

### アニメーションミキシングは同一 `.ssab` 内のみ

アニメーションは**トラック**に積んで合成します（track 0 を土台に、その上のトラックが順に重なります）。積む際には 4 つの必須条件があります。

- **同一 `.ssab` であること。** リソースをまたぐ合成はサポートされません。
- **同一パーツに同一セルを割り当てていること。** セルのメタデータは **track 0** から取得されるため、セルが異なるとサイズ・pivot の不一致が生じ、ポーズが目に見えて崩れます。同一 `.ssae` 内のアニメーション同士であれば通常は問題ありません。
- **離散的な属性は合成されないこと。** セル・パーツカラー・シェーダー・反転・非表示・描画順・テクスチャは **track 0** のメインアニメーションから取られ、track 0 でクロスフェードが始まると入ってくる側に切り替わります。そのため、重ねたトラックでセルを差し替えることはできません。差し替えるには[パーツの上書き](../overview/runtime-changes.md)を使います。
- **パーツ単位のマスクはないこと。** トラックが影響する範囲は、そのアニメーションがキーを持つパーツで決まり、一部のパーツだけに限ることはできません。

副次的な挙動も 3 点あります。`parts_color` を持つパーツの見た目の α は、合成結果ではなく **track 0** 由来になります。イベントは既定で **track 0** のメインアニメーションのみが発火します（他のソースの発火しきい値は既定で `+∞` のため、発火させるにはそのソースのしきい値を下げます）。また尺の違うソースは独立したクロックで進むため、揃えるのは Player 側の責任です。

インスタンスパーツとエフェクトパーツは合成の外にあります。どちらも 1 つのアニメーションではなく `.ssab` に属するため、track 0 のクロスフェードでも作り直されずに動き続け、切り替えをまたいでどちらのアニメーションのキーが効くかは合成されません。

### メッシュ（スキン）パーツには直接追従できない

追従させたものは、追従先のパーツの変換を受け取ります。メッシュパーツの頂点はボーンのスキニングで動きますが、パーツ自身の変換はセットアップ時の位置に残るため、メッシュパーツに追従させたものは見えている絵の上ではなく、キャラクターの原点の近くに置かれます。

**対処:** SpriteStudio でその位置に NULL パーツかボーンパーツを足し、そちらに追従させてください。

## 🧩 Player 側が用意するもの

`libssruntime` が担うのはアニメーションの **状態計算** です。次の 2 つはホストエンジンとの連携が必要なため、意図的に Player 側の責務としています。

| 機能 | ランタイムが提供するもの | Player 側で実装が必要なもの |
|---|---|---|
| **テキストパーツ** | 作画された文字列と、ビットマップフォントのプロジェクトではそのグリフアトラス。描画プラン上の位置も確保されるため、他のパーツと同じく優先度順に合成されます | グリフのレイアウト、アウトラインフォントのラスタライズ、描画呼び出し（ホストエンジンのテキスト機能を使用） |
| **オーディオ** | 再生指示イベント（ファイル名・発火タイミング） | エンジンのオーディオシステムによる実際の再生 |

例外として、**マスクとして作画されたテキストパーツ**は描画プランに含まれません。カバレッジを書き込むためのグリフをランタイムが持たないためです。

### テキストパーツと 9 スライスパーツは、どの Player でもまだ描画されない

次の 2 つのパーツ種別は、データとしては Player まで届きますが、現時点で **どの公式 Player にも**実装がありません。これはエンジン間の差ではなく共通の状況です。

- **テキストパーツ** - ランタイムは作画された文字列、ビットマップフォントのグリフアトラス、描画プラン上の位置を提供します。グリフを描画する Player はまだありません。
- **9 スライスパーツ** - ランタイムはグリッド全体を専用バッファ（`Nines` バッチ）に構築し、アップロードできる状態にします。そのバッファを読む Player がまだないため、セルが引き伸ばされた状態ではなく何も表示されません。

どちらも描画順序上の位置は保持されるため、これらを使ったアニメーションはエラーにならず、該当パーツが欠けた状態で再生されます。

**対処:** 現時点で出荷するデータでは、作画時に通常パーツへ置き換えてください。

## 🖌️ 描画に関する制約

### 9 スライスパーツは UV アニメと回転配置セルを反映しない

**UV アニメ属性**と、**セルマップ内で回転配置されたセル**は 9 スライスパーツには適用されません。グリッドはセル矩形のみから生成され、オーサリングツールの挙動に合わせられています。

### 描画先を参照するブレンドは下が不透明であることを前提とする

`Mul`・`Sub`・`Screen`・`Exclusion`・`Invert` は描画先のピクセルを読み取るため、エディターと一致するのは下のピクセルが **不透明** な場合のみです（SpriteStudio 自身がその前提で描画するため）。

**対処:** エディターとの厳密な一致が必要なら、ブレンドを多用するアニメーションには不透明な背景レイヤーを敷いてください。

なお、そのブレンドモードをエンジンが *そもそも再現できるか* は Player ごとに異なる別の問題です。[Player ごとの違い](../overview/player-differences.md) を参照してください。

## 📦 配布と読み込み

### スキーマ版の合わない `.ssab` は読み込めない

`.ssab` / `.ssqb` はバイナリにスキーマ版を持ち、ランタイムは自分が読める版と一致しないファイルの**読み込みを失敗させます**。Rust とブラウザ（wasm）のフェイスではエラーの文に両方の版が入りますが、C ABI の文は「Invalid SSAB version」だけで、2 つの版は `ss_runtime_ssab_schema_version()` とパック自身の `version` フィールドで得ます。途中まで読めることも、古いスキーマで作ったアセットが黙って動き続けることもありません。

**対処:** Player が使っている SDK の版でアセットを作り直してください。ホスト型のコンバーターが[スキーマ版ごとに公開されている](../overview/convert-with-a-standalone-tool.md)のも同じ理由です。

### `.ssab` の入力検証は行われない

パフォーマンスの最大化とバイナリサイズの最小化（組み込み／WASM 向け）のため、ランタイムは読み込む `.ssab` の **構造検証を行いません**。破損したデータや悪意を持って細工されたデータを読み込むと、範囲外アクセス・未定義動作・クラッシュを引き起こす可能性があります。

**対処:** 信頼できるアセットのみを読み込んでください。ネットワーク経由やユーザー入力から
`.ssab` を動的にロードする製品では、事前に自前で検証するか、同梱アセットのみに読み込みを限定する設計にしてください。

### embedded モードの `.ssab` には 2 つの制約がある

`.ssab` は、参照アセットをバイナリ自身に埋め込む *embedded* モードで生成できます。これには
2 つの制約が伴います。

- **キーはアセットのファイルパス。** 埋め込みは `.sspj` / `ss*e` に記載されたアセットのファイルパスをキーとするため、プロジェクト内でパスが重複すると **競合** します。アセットのファイルパスは重複しないようにしてください。
- **埋め込まれるのは、そのアニメーションパックが実際に使うアセットのみ。** *外部インスタンス*として参照される別の `.ssab` の本体は含まれないため、参照先の `.ssab` は別途用意して配布してください。

### ブラウザでは WebAssembly SIMD が必須

ランタイムの WASM ビルドは **WebAssembly SIMD 命令** を使用しており、**SIMD 非対応のブラウザでは動作しません**。どの Player でも、Web 向けのターゲットはすべて対象です（RPG ツクール MZ のプラグインは SIMD を使わないビルドを同梱しているので対象外です）。

**対処:** 配信先のブラウザ要件として、WebAssembly SIMD 対応を前提としてください。
