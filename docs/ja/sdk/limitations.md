# ⚠️ 共通の制限事項

このページの内容はすべて **共通コア**（`libssruntime` / `libssab`）に由来するため、エンジンを
問わず **すべての公式 Player に当てはまります**。各 Player のドキュメントには、その Player に
固有の事項のみが記載されています。Player 間の差分は
[機能サポート状況](../overview/feature-support.md) を参照してください。

!!! tip "正典の所在"
    実装レベルの完全な一覧は SDK の Player 移植ガイド
    （[`libs/ssruntime/docs`](https://github.com/cri-middleware/SpriteStudio-SDK/tree/HEAD/libs/ssruntime/docs)
    の *Introduction → Limitations*）にあります。このページはその利用者向け要約です。

## 🎬 再生・タイムライン

### `independent = true` パーツは逆再生・シークで正しく動作しない

`independent = true` を設定したインスタンスパーツ／エフェクトパーツは、親のタイムラインから
切り離され **自身のリアルタイム時計** で進行します。そのため親の **逆再生** と **シーク** で
破綻します（リアルタイム時計は過去方向に戻れず、任意の過去フレームにおける「子の累積時間」も
一意に定まらないため）。順方向の再生は、順方向のフレームスキップを含めて正しく動作します。

**対処:** 逆再生やシークを行う可能性のあるアニメーションは、`independent = true` を使わない
構成で制作してください。やむを得ず使用する場合は、その子インスタンスが順方向再生時のみ
正しく描画されることを Player の利用者に明示してください。

### シークは通過したフレームのイベントを発火しない

再生位置を直接ジャンプさせた場合（フレーム指定）、発火するのは **移動先フレーム** の
`UserData` / `Signal` / `Audio` イベントのみで、通過した各フレームのイベントは発火しません。

**対処:** 中間のイベントも漏れなく処理したい場合は、ジャンプではなく `update()` を複数回
呼んで少しずつ進めてください。

### オーディオは逆再生できない

サウンドイベントが発火するのは、アニメーションが時間軸上を **順方向** に進んでいる間のみです。
実質的な進行方向が逆向き（逆再生、ピンポンの復路、負の再生速度）の場合、オーディオイベントは
スキップされます。一般的なオーディオバックエンドが音声の逆再生を提供していないためです。

### アニメーションブレンドは同一 `.ssab` 内のみ

アニメーション同士の重み付きブレンド／クロスフェードには、2 つの必須条件があります。

- **同一 `.ssab` であること。** リソースをまたぐブレンドはサポートされません。
- **同一パーツに同一セルを割り当てていること。** セルのメタデータは primary ソースから
  取得されるため、セルが異なるとサイズ・pivot の不一致が生じ、ポーズが目に見えて崩れます。
  同一 `.ssae` 内のアニメーション同士であれば通常は問題ありません。

副次的な挙動も 2 点あります。`parts_color` を持つパーツの見た目の α は、ブレンド結果ではなく
**primary** ソース由来になります。またイベントは既定で primary ソースのみが発火します
（ソースごとに発火のしきい値を持つため）。

### シーケンス（`.ssqe` / `.ssqb`）再生は未実装

変換ではすでに `.ssqb` を生成できますが、ランタイムでのシーケンス再生は
[SDK のロードマップ](https://github.com/cri-middleware/SpriteStudio-SDK/blob/HEAD/ROADMAP.md)
上の項目で、ランタイムのステートマシンと合わせて実装される予定です。

## 🧩 ランタイムが描画までは行わない機能

`libssruntime` が担うのはアニメーションの **状態計算** です。次の 2 つはホストエンジンとの
連携が必要なため、意図的に Player 側の責務としています。

| 機能 | ランタイムが提供するもの | Player 側で実装が必要なもの |
|---|---|---|
| **テキストパーツ** | 作画された文字列と、ビットマップフォントのプロジェクトではそのグリフアトラス。描画プラン上の位置も確保されるため、他のパーツと同じく優先度順に合成されます | グリフのレイアウト、アウトラインフォントのラスタライズ、描画呼び出し（ホストエンジンのテキスト機能を使用） |
| **オーディオ** | 再生指示イベント（ファイル名・発火タイミング） | エンジンのオーディオシステムによる実際の再生 |

例外として、**マスクとして作画されたテキストパーツ**は描画プランに含まれません。カバレッジを
書き込むためのグリフをランタイムが持たないためです。

したがって、テキストパーツが描画されるか、サウンドが実際に鳴るかは **Player ごと** の性質です。
[機能サポート状況](../overview/feature-support.md) を確認してください。

## 🌐 ブラウザでは WebAssembly SIMD が必須

ランタイムの WASM ビルドは **WebAssembly SIMD 命令** を使用しており、**SIMD 非対応の
ブラウザでは動作しません**。Web 向けのすべてのターゲット（Web Player 群、Godot の Web 書き出し、
Flutter Web、Ren'Py Web）が対象です。

**対処:** 配信先のブラウザ要件として、WebAssembly SIMD 対応を前提としてください。

## 🔐 `.ssab` の入力検証は行われない

パフォーマンスの最大化とバイナリサイズの最小化（組み込み／WASM 向け）のため、ランタイムは
読み込む `.ssab` の **構造検証を行いません**。破損したデータや悪意を持って細工されたデータを
読み込むと、範囲外アクセス・未定義動作・クラッシュを引き起こす可能性があります。

**対処:** 信頼できるアセットのみを読み込んでください。ネットワーク経由やユーザー入力から
`.ssab` を動的にロードする製品では、事前に自前で検証するか、同梱アセットのみに読み込みを
限定する設計にしてください。

## 📦 embedded モードの `.ssab`

`.ssab` は、参照アセットをバイナリ自身に埋め込む *embedded* モードで生成できます。これには
2 つの制約が伴います。

- **キーはアセットのファイルパス。** 埋め込みは `.sspj` / `ss*e` に記載されたアセットの
  ファイルパスをキーとするため、プロジェクト内でパスが重複すると **競合** します。アセットの
  ファイルパスは重複しないようにしてください。
- **埋め込まれるのは、そのアニメーションパックが実際に使うアセットのみ。** *外部インスタンス*
  として参照される別の `.ssab` の本体は含まれないため、参照先の `.ssab` は別途用意して
  配布してください。
